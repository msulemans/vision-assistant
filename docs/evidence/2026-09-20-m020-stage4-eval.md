## The three misses (each diagnosed, none averaged away)

- **m08 "open the last story on page two"** (navigate): the model clicked the
  **pagination control** (`ui:19` → `/news/page3//`) instead of the story
  link, then clicked it again — the duplicate-outcome guard ended the run
  (`blocked:no_progress`). Wrong-target selection, model-side; the guard
  behaved as designed.
- **m17 "compact on, timestamps off"** (form): the model toggled timestamps
  off, then **flip-flopped** (`ui:7` off → `ui:7` on → `ui:5` again → `ui:6`
  (dark, not asked) on → `ui:7` off → `ui:7` on), saved the wrong final state
  (`show_timestamps` stayed on), then **stopped** admitting the mismatch
  ("…timestamps are on (not off)…"). Oscillation is not a repeat — no guard
  fires by design — and the model self-terminated at 10 calls. Model-side
  state-tracking failure.
- **m18 "query + category + per-page 10"** (form): filled query ✓ and
  category ✓, **skipped per-page**, tried to save with a stale observation id
  (refused, correctly), re-observed, saved ✓, then saved AGAIN (another stale
  id) → the extra save executed and the duplicate-outcome guard ended the
  run. The c11-class "save before all fields" failure, now at scale;
  per-page stayed at its default.
