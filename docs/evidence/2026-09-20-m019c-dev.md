## Two runs, one documented revision

**Run 1** — task set v1 (c01–c05) with prompt `m019a-v1`:
`runs/m018/m019c-dev-20260920-124528/summary.json`, **1/5 expected**
(only the refusal matched). The raw answers exposed two problems:

1. *Authoring errata (fixed by re-authoring, not tuning):* c01 asked for a
   story code on the news list — codes are only visible on story pages, and
   answer mode cannot navigate. The model answered with the title in the
   code field; the task was unanswerable as written.
2. *Prompt-shape confusion:* the typed prompt showed no exact reply shapes,
   so the model emitted `click_target` without `observation_id`, and used
   `value` where `fill_field` needs `text` / `select_option` needs `option`.

**The single permitted revision** — prompt `m019c-v2` (`browser_agent`,
documented in-source): exact reply shapes for every action the mode allows,
the hard requirement of `target_ref` + `observation_id` for target actions,
and explicit field-name guidance (`text` / `option` / `value`). Paired with a
**fresh five-task set** (c06–c10), per the plan.

**Run 2** — fresh set v2 with prompt `m019c-v2`:
`runs/m018/m019c-dev-20260920-124833/summary.json`, **4/5 expected**.
