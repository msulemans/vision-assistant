## Question

M023 measured the released Cua-S1-FORMS scorer at 1/4 on the four dev form
tasks: confident skips outside its trained label vocabularies, one confuser
fill. Can a 706K-parameter specialist be adapted to *this* form family —
settings toggles with on/off goals, preference fields with confusable
values, draft title/body cross-swaps, receipt e-mail near-misses — and then
match the vision baseline behind the same frozen harness?

## Method (all revisions frozen pre-measurement; `docs/M024_S1_FORMS_VA_PLAN.md`)

- **Contract v3–v7** (`src/vision_assistant/cua_s1_provider.py`): the
  element context carries a trusted **goal-clause hint**
  (`goal_hint()` — exact label substring, then every-token clause, then
  any-token; quote-aware clause splitting), and the TASK line is capped at
  a clause boundary (96 chars) so the hint always survives the scorer's
  **224-byte context window**. The hint only localizes goal text; the
  specialist still chooses the option. Decision document version
  `s1-forms-va-decisions-v3`.
- **Corpus** (`scripts/s1_forms_va_generate.py` → `runs/s1-forms-va-corpus8`):
  17,557 train / 1,986 val rows sampled from the same family; document
  labels and visible labels deliberately decoupled (short forms like
  `Category` for a field shown as "Default category"); select fields
  rendered with both the `Select` and the harness's nearest-role `Edit`.
- **Training** (`scripts/s1_forms_va_train.py`): fine-tune from the
  RELEASED weights (safetensors sha `05954c1c…`, signature validated),
  14 epochs, AdamW 1e-3, warmup+cosine, grad clip 1.0; best epoch selected
  by **macro per-action accuracy** (nll tiebreak); per-epoch checkpoints;
  CPU only, deterministic.
- **Scoring** (`scripts/cua_s1_scoring.py --weights models/s1-forms-va-v7`):
  one forward pass per real-case element; pinned decisions document
  consumed by the stdlib-only provider (strict validation).

The decisive pre-measurement find: with the real c17 goal (123 chars) the
element hint's value fell past the scorer's 224-byte window and the
category element misbound to the query field (0.913). Probe: trimming the
goal flips the same element to the correct option at 0.995. The cap fixed
it — this was a renderer bug, not a model failure.

  not modified; the specialist sits behind the same typed loop with zero
